# 描述协议 Protocols

开放层元素（隐喻、角色、中央主体）**不从库中选取，而是为当次内容现场推理**。
本文件规定：推理产出必须长什么样、达到什么标准才算合格。
`examples/` 下的卡片是"合格描述的示范"，不是备选项。

## §0 总标准：可验证性
描述中的每一句话，都必须能在最终成品图上检查真伪。

| ✗ 不可验证（禁止） | ✓ 可验证（要求） |
|---|---|
| 画面有冲击力 | 主体占画面高度 50-60%，从底边出血 |
| 火箭充满希望 | 火箭呈 75° 仰角，尾焰为 accent 橙红色，喷向左下 |
| 角色很可爱 | 头身比 1:1.5，眼睛占脸部 40%，全部轮廓为圆角 |
| 富有历史感 | 边缘做 2-5% 透明度的焦痕，角落一枚直径 5cm 蜡封 |

写完描述后逐句自查：这句话能拿着成品图打勾打叉吗？不能就重写。

## §1 隐喻协议（场景类 narrative 使用，如 N1/N4）

### 第一步：定基调（由 HERO.nature 驱动）
| nature | 场景基调 | 方向感 |
|---|---|---|
| positive | 上升/抵达/收获类（发射、登顶、升空、丰收、开闸） | 视觉动线向上或向目标汇聚 |
| steady | 旅程/探索/运转类（河流、森林、铁路、车间日常） | 平稳横向推进 |
| adverse | 挑战类**但必须有出路**（风浪中见灯塔、过山车有缓冲区、迷宫有出口） | 起伏，终点处给到稳定锚点 |
| complex | 系统类（工厂、生态、枢纽、人体、城市） | 多线汇入一个整体 |

基调只约束类别，具体场景**优先从基金/投资语义生发**：净值曲线可以化为山路、定投是沿途补给、复利是滚雪球、资产配置是船队编组、回撤陪伴是风浪中驶向灯塔的航船。S4 投教可用生活化类比（做菜/园艺/旅行），但场景元素必须能回扣投资概念（mapping 表中逐条对应）。
**合规画面约束**：禁止画面隐含收益承诺意象——金币雨、印钞机、躺赢、保险箱锁住收益、一路只涨的曲线（曲线必须有波动）；adverse 场景禁止坠落/沉没/破产等恐慌意象。

### 第二步：填满隐喻卡（缺一字段即放弃此隐喻，换一个）
```yaml
metaphor_card:
  name:            # 场景名，如"火箭发射台"
  trigger:         # 适用条件，如"positive + 有明确目标值"
  one_line:        # 一句话场景描述
  mapping:         # 【灵魂字段】契约概念 → 场景元素，逐条对应
    - concept: <POINTS[01] 的概念>   element: <场景中的具体物件>
    - concept: <POINTS[02] 的概念>   element: ...
    - concept: <HERO>                element: <场景的高潮物/目标物>
    # 每个将出现在画面上的契约概念都必须有锚点
  composition:     # 构图：主体占比%、视角、出血方式
  route:           # 导览/时间动线如何穿过场景（起点→…→终点）
  anchors:         # 各信息槽位附着在场景的哪个位置
  must_avoid:      # 此隐喻特有的回避项（如"火箭不得画成卡通玩具感"）
```

### 合格判据
- mapping 覆盖所有上画的契约概念，且对应关系经得起追问（"为什么燃料仓=政策支撑？"——因为政策是持续供能项，说得通）
- 场景能physically容纳所选 narrative 的全部槽位锚点而不拥挤
- 与 HERO.nature 不冲突（adverse 不庆祝，positive 不阴郁）

## §2 角色协议（storybook-guide + N1 使用）

### 必须产出的角色卡
```yaml
character_card:
  archetype:       # 原型方向：机器人 / 拟人精灵 / 拟人动物（按主题气质选：科技感→机器人，自然温和→动物，传统亲和→精灵）
  species_or_form: # 具体形态及理由，如"猫头鹰——内容是知识科普，取其智慧意象"
  silhouette:      # 剪影描述：头身比、体型轮廓（必须缩到 5% 画幅仍可辨认）
  face:            # 眼睛占比、五官规则
  outfit_props:    # 服装/道具 ≤3 件，须与内容领域相关（咖啡科普→围裙+量勺）
  palette:         # 使用 style 的 guide_character 色 + ≤2 个点缀色
  expressions:     # 4-5 个表情姿态，对应出场节点（开场欢迎/中途解说/记录/结尾总结）
  consistency:     # 版内不变项清单（外观/服装/配色）
  must_avoid:      # 至少含：不得近似任何已有知名 IP；不得写实恐怖谷
```

### 合格判据
- 剪影测试：仅凭轮廓描述能想象出唯一形象
- 原创性：与知名 IP（皮卡丘、大白、米老鼠等）无可指认的相似
- 领域呼应：道具/配饰与内容主题有一处明确关联

## §3 中央主体协议（classical-oil + N2 使用）

为肖像陈列推理"画什么"。三个方向（按 HERO 形态选）：
1. **人物肖像**：内容主角或象征人物，严肃/思考姿态，背景为与领域相关的历史空间（交易所/实验室/书房/工坊），soft focus。
2. **象征静物**：领域核心物件的古典静物画（咖啡科普→铜壶与生豆；年报→账本与天平），周围环绕 2-3 件呼应器物。
3. **概念拟人**：抽象概念人格化为 19 世纪装束人物，手持 1-2 件属性道具（天平=权衡，望远镜=远见，沙漏=时间）。

产出字段：`subject_choice`（选哪个方向+理由）、`figure_or_object`（主体的具体描述：姿态/朝向/服饰或材质）、`props`（道具及其象征，逐条）、`background`（历史空间，soft focus）、`light`（侧光方向：哪侧金黄哪侧紫棕）、`must_avoid`。
**真实在世人物默认不入画**；用户内容涉及具体人物时改用象征化处理（背影、剪影、器物代指）或与用户确认。

## §4 归档格式（Step 6 使用）
新隐喻/角色经用户认可后，按上述卡片 yaml 原样存入 `examples/metaphors/<name>.md` 或 `examples/characters/<name>.md`，文件头部加两行：
```
# <中文名>（<适用基调>）
来源：<日期>，<内容领域>项目沉淀
```
归档时将领域专有数值泛化为 `<HERO数值>`、`<POINTS[01]概念>` 等占位符，使卡片可跨领域复用。

## §5 排版力量协议（magazine-editorial 使用；无场景隐喻时的视觉冲击来源）

当视觉冲击**不来自插画/隐喻，而来自版式张力本身**时使用本协议。magazine-editorial 是天然载体，其他 style 在 N2/N3 模式下也可借用。

### 三个核心张力轴
1. **字号跨度**：同一版面最小字（6pt 页脚）与最大字（超大 Display 标题）≥8× 差距。填写字号规划表：
   - hero_size: （数据展示，如 120pt）
   - headline_size: （封面大标题，如 60-80pt）
   - section_size: （栏标签，如 14pt 全大写）
   - body_size: （正文，如 10pt）
   - caption_size: （标注/页脚，如 6-7pt）
2. **字重对比**：同族字体 font-weight 100（极细）与 900（极粗）并置；或衬线细笔画与无衬线粗黑并置。明确写出哪两处字重对比是视觉锚点。
3. **留白比例**：明确规划负空间——某列/某区域的**留白面积**（不是剩余面积，是主动设计的呼吸带），写出"XX 区域留白率约 Y%"。留白率 <30% 的版面须在 must_avoid 中标注"禁止再加任何装饰"。

### 产出字段（magazine-editorial 的"隐喻卡"替代品）
```yaml
typography_impact_card:
  font_size_plan:
    hero: Xpt    headline: Xpt    section: Xpt    body: Xpt    caption: Xpt
  weight_contrast_anchors: ["<处1，如'标题 font-weight 100 极细衬线'>", "<处2>"]
  whitespace_plan: ["<区域> 留白率约 X%", ...]
  asymmetry_rule: # 打破对称的具体方式（如"正文栏占宽 60%，右侧 40% 全部留白"）
  accent_discipline: # accent 色的唯一用途声明（如"仅用于数据数字与金属细分隔线"）
  must_avoid: ["不得填满每个栏位", "不得用插画填补留白（留白就是设计）", ...]
```

## §6 UI 隐喻协议（pixel-game 使用；界面即叙事容器）

当内容装入一个**虚构界面系统**（游戏/终端/操作系统/仪表盘）时使用。界面的 UI 元数据（血量条/对话框/物品栏）本身承担信息结构，而非单纯装饰。

### UI 系统选择（为当次内容推理，不从库中硬套）
推理步骤：
1. 内容性质 → 匹配界面类型：解读/分析→RPG任务日志或指挥控制台；陪伴→聊天界面或信件系统；投教→教程关卡或图鉴系统；宣传→商店/展示厅界面
2. 受众气质 → 选 UI 年代感：怀旧向→FC/Game Boy（16色，5px字）；现代向→像素 indie（32色，流畅像素）；赛博向→终端黑屏绿字

### 契约概念 → UI 元件映射（必须填满）
```yaml
ui_metaphor_card:
  system_name: # 虚构界面名，如"MARKET_OS v2.42" / "基金图鉴" / "投资副本"
  ui_era: fc_8bit | indie_16bit | cyberpunk_terminal  
  interface_type: # 具体界面类型（RPG对话/物品栏/任务日志/商店/HUD）
  concept_to_ui_mapping:
    - concept: <TITLE>              ui_element: 游戏窗口标题栏（带最小化/关闭像素按钮）
    - concept: <DATA>               ui_element: RPG属性条（████░░ XX%格式）or 数字跳动框
    - concept: <BODY节点×N>         ui_element: 任务日志条目/NPC对话框/物品说明框/商店条目
    - concept: <VOICE>              ui_element: NPC 头像框（32×32 像素）+ 对话框（三角指向）
    - concept: <LIST>               ui_element: 物品栏格子（3×N 网格，稀有度彩色边框）
    - concept: <CAUTION>            ui_element: 系统警告框（红色边框闪烁）或滚动公告栏
    - concept: <META>               ui_element: 底部系统消息框（半透明黑底+小号像素字）
  ui_chrome_elements: # 纯装饰性 UI 元件（不承载内容）
    - 公告滚动栏（header 下）
    - CRT 扫描线纹理覆盖（10% 透明度）
    - 像素光标图标（在关键位置）
    - 像素分隔线（分节用，3 种图案选一）
  must_avoid: ["不得让 UI 框架喧宾夺主（装饰面积 ≤ 30%）", "中文必须用点阵字体（不得模糊）", ...]
```

## §7 光效协议（blueprint-system 使用；光效是工艺约束的一部分）

当风格的视觉冲击来自**发光/光效本身**（而非色彩、插画或版式）时，光效必须系统化规划，否则全画面发光 = 没有发光。

### 光效层级（必须明确）
```yaml
glow_hierarchy_card:
  level_1_hero_glow:  # 最强：HERO 数值/中心主体，outer glow 6-10px blur 15px opacity 90%
  level_2_structure_glow:  # 中强：结构线/框架，outer glow 3-5px blur 10px opacity 70%
  level_3_label_glow:  # 弱：标注线/次要文字，outer glow 1-2px blur 5px opacity 40%
  level_4_ambient:  # 极弱：背景网格，无发光，只靠颜色与背景区分
  glow_color_per_element: # 哪个内容层用哪个发光色（从 palette 的 extras.glow 取）
  must_avoid: ["全画面等强度发光（视觉噪声）", "发光色超过3种（palette extras.glow 约束）", "发光盖过文字可读性"]
```

### 光效辅助元素（blueprint 特有）
- 背景网格：主网格 50px opacity 20%，细网格 10px opacity 8%（**不发光，靠微弱颜色区分**）
- 测量刻度：画面边缘标尺（顶/左），刻度线 0.5px，数字 6pt；比例参考 scale bar
- 坐标标注：callout 细线 0.5px + 箭头，指向场景关键节点，文字 6-7pt 等宽
- 等轴测剖面（causal 拓扑专用）：30° 等轴测投影，层间距均等，每层半透明填充 10-20%，边缘 structure_glow
