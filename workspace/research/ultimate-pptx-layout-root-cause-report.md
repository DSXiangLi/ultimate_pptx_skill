# Ultimate PPTX Layout Root-Cause Report

## Trigger

The 15-slide `glass-fintech-pptx` benchmark appeared to pass automated validation, but manual review found visible layout defects: text overlap, title/card collisions, and container/text crowding.

## Confirmed Failure Mode

The defect was real. A forensic IR scan found that the generated benchmark contained many layout issues before the fix, including:

- metric `value` and `delta` text boxes geometrically overlapping;
- table/top metric bands sitting too close to titles;
- dense tables passing despite projector-readability risk;
- visual QA sampling missing some pages.

The clearest concrete example was Slide 10 before the fix:

```text
b10_metric_1_value: y=178 h=38
b10_metric_1_delta: y=192 h=24
```

These boxes overlap vertically by 24 px. This was generated by the shared `add_metric()` function, so it affected many slides, not one slide.

## Why Previous Validation Missed It

### 1. Visual fidelity was measuring renderer consistency, not design correctness

The existing visual loop compared:

```text
IR/Pillow reference PNG vs LibreOffice-rendered PPTX PNG
```

If the IR itself contains bad layout, both images can contain the same bad layout and still score highly.

### 2. QA focused on editability/export audit

The export audit proved that text/chart/table objects were native editable objects, but editability does not imply good layout.

### 3. The first layout gate was incomplete

It checked safe zones, text capacity, bottom rails, and some table heuristics, but it did not check:

- pairwise text collisions;
- metric-card internal label/value/delta stacking;
- child padding inside a card;
- visual title/card band separation.

### 4. Visual review was sampled, not exhaustive

The earlier manual/AI visual pass looked at a few representative pages. It did not enforce every page and every repeated component.

## Fix Implemented

### New blocking checks in `scripts/check_layout_safety.py`

- `TEXT_BOX_COLLISION`
- `METRIC_TEXT_COLLISION`
- `METRIC_CHILD_Y_PADDING`
- `TABLE_TOO_DENSE`
- `TABLE_ROW_TOO_SHORT`
- existing safe-zone/footer/title-decor checks retained

### Compiler fixes in `scripts/compile_spec_to_ir.py`

- Replaced fixed metric y offsets with intrinsic metric-card text stack layout.
- Increased/rebalanced compact metric card heights instead of shrinking text below 10 px.
- Reduced title size for content-heavy topologies.
- Moved table metric band down and separated it from the title band.
- Reduced over-dense allocation table rows for projector-safe readability.

### Contract wording fix

The compliance page no longer uses internal “PPTX generation/test” language.

## Current Verification

`python3 scripts/validate_glass_benchmark.py` now reports:

```text
PASS glass benchmark slides=15 score=95.76 editability=100.00 layout=pass
```

Focused visual re-checks for Slide 05, Slide 10, and Slide 14 returned `通过` for:

- no metric-card text overlap;
- no title/card collision;
- no table/source/risk-note overlap;
- compliance wording no longer has test/generation-chain language.

## Prevention Architecture

Going forward, the release stack should be treated as four independent gates:

1. **IR structural gate** — object ids, roles, z-order, editability policy.
2. **Layout/text safety gate** — estimated text capacity, pairwise collisions, card intrinsic layout, table density, footer separation.
3. **Renderer fidelity gate** — expected vs actual render similarity.
4. **Human/AI semantic review gate** — narrative coherence, finance professionalism, compliance wording, visual hierarchy.

No single score should substitute for all four.


## Second Fix Pass: Text Leading and Container Collisions

A later review found remaining defects after metric overlap was fixed:

- text lines were sometimes visually too tight in wrapped native PPTX objects;
- containers could overlap, double-frame, or press into each other without triggering text collision rules;
- table page titles still needed larger title-to-metric breathing room.

### Additional Root Causes

1. `export_ir_pptx.py` did not write explicit paragraph line spacing, so native Chinese text relied on renderer defaults.
2. `check_layout_safety.py` lacked a visual-container model. Table/chart objects already export their own panels, so wrapping them in another glass panel created double containers.
3. Title-to-content separation was still treated as visual taste rather than a release-blocking metric.

### Additional Fixes

- Added explicit OOXML paragraph leading (`a:lnSpc`) for native text.
- Added blocking `CONTAINER_OVERLAP`, `NESTED_CONTAINER_DOUBLE_PANEL`, and `TITLE_CONTENT_GAP_TOO_SMALL` checks.
- Removed redundant table outer panels, shortened overlapping note panels, split action-page KPI and body zones, and increased table title-to-metric spacing.

### Updated Verification

`python3 scripts/validate_glass_benchmark.py` now reports:

```text
PASS glass benchmark slides=15 score=96.01 editability=100.00 layout=pass
```

Focused visual review found Slides 05, 06, 09, 10, 11, 12, and 15 passing for text line spacing and container overlap.


## Third Fix Pass: CJK Render Scale, Protected-Term Wraps, and Alignment Gates

A later user review correctly identified that screenshots still showed professional typesetting defects even after overlap/container gates passed: title/body crowding, text-container alignment issues, and Chinese short terms split across line breaks.

### Additional Root Causes

1. The CJK capacity heuristic still underestimated native Office/LibreOffice text width. Chinese text behaved closer to `font_size * 1.30`, not `font_size * 1.0`.
2. Box-level capacity checks do not catch bad line-break semantics. A text box can be large enough while still splitting `评审版本`, `形成`, `先进制造`, or `AI算力` in a visually unprofessional way.
3. Layout safety lacked explicit grid-alignment checks for paired panels, metric rows, and action-page card/body spans.

### Additional Fixes

- Added conservative Office-like `TEXT_RENDER_SCALE = 1.30` to compiler and checker.
- Added blocking `PROTECTED_TERM_WRAP_RISK`, `TITLE_ORPHAN_WRAP`, `TITLE_TEXT_GAP_TOO_SMALL`, `CONTENT_ROW_TOP_MISALIGNMENT`, and `CARD_ROW_EDGE_MISALIGNMENT` checks.
- Shortened benchmark copy/labels where components were too dense for robust native PPTX rendering.
- Regenerated and visually reviewed the 15-slide benchmark contact sheet.

### Current Verification


Final rendered review found no blocking issues for title/content overlap, obvious container misalignment, Chinese short-term splitting, truncation, or text squeeze. Remaining suggestions are non-blocking density/readability refinements on table/compliance/action pages.
